    \section{Part I: Security Policy}

        A security policy is just a set of rules that say who can do what. We split our rules into four goals:
        confidentiality, integrity, availability, and conflict of interest.

        \subsection[Confidentiality]{Confidentiality: Keep Student Data Private}

            \begin{itemize}
                \item A student can see only their own profile, grades, and registration.
                \item A faculty member can see students only in their own course.
                \item Registrar staff can see records they need for their job, not everything.
                \item Research data is shared only with people who are allowed to see it.
            \end{itemize}

        \subsection[Integrity]{Integrity: Keep Grades and Records Honest}

            \begin{itemize}
                \item Only faculty can enter grades, and only for their own course.
                \item Students can never write or change a grade.
                \item Grade changes happen only inside the grading period, and get logged.
                \item Registration and transcript records can change only through approved steps.
            \end{itemize}

        \subsection[Availability]{Availability: Keep the Portal Working}

            \begin{itemize}
                \item Students and faculty can reach registration and grades during normal hours.
                \item The system is backed up, so IT staff can restore it if something breaks.
            \end{itemize}

        \subsection[ConflictOfInterest]{Conflict of Interest: Keep Research Separate}

            \begin{itemize}
                \item If a researcher works with one company's or group's private data, they cannot also work
                    with a rival group's private data.
                \item A researcher must pick one side before touching sensitive research data.
            \end{itemize}

    \pagebreak

            \begin{defbox}[Definition: three ground rules]
                \textbf{Least privilege}: give each user only the access they need, nothing more.
                \textbf{Separation of duties}: split sensitive tasks so one person cannot do everything alone
                (e.g. entering a grade and approving it).
                \textbf{Default deny}: if a rule does not clearly allow something, the system blocks it.
            \end{defbox}

        \subsection[Rules]{Simple Rules by Role}

            \begin{itemize}
                \item \textbf{Student}: read own data, read own grades, request own registration. Nothing else.
                \item \textbf{Faculty}: read/write grades and materials, but only for their own course.
                \item \textbf{Registrar}: read/write registration and official records, no research data.
                \item \textbf{Researcher}: read/write one research group's data at a time, never two rival
                    groups.
                \item \textbf{Admin}: manage accounts and settings, but not routine access to grades or research
                    data.
            \end{itemize}

    \section{Part II: Subjects and Objects}

        In access control, a \textbf{subject} is who is asking for access. An \textbf{object} is what they are
        trying to access.

        \begin{defbox}[Definition: subject vs. object]
            A \textbf{subject} is an active user or process that requests access, like a student logging in.
            An \textbf{object} is a passive resource being protected, like a grade record.
        \end{defbox}

        \subsection[Subjects]{Subjects: Who Is Asking}

            \begin{itemize}
                \item Student
                \item Faculty (instructor)
                \item Registrar / academic staff
                \item Researcher
                \item System administrator
            \end{itemize}

        \subsection[Objects]{Objects: What Is Being Protected}

            \begin{itemize}
                \item Student profile and personal data
                \item Registration records
                \item Grades and transcripts
                \item Course materials and faculty collaboration files
                \item Research datasets (grouped by which side the researcher is on)
                \item Audit logs
                \item System settings
            \end{itemize}

    \pagebreak

    \section{Part III: Access Control Model}

        We pick \textbf{Role-Based Access Control (RBAC)} as the main model. Here is why:

        \begin{itemize}
            \item The portal already has clear roles: student, faculty, registrar, researcher, admin.
            \item In RBAC, access is tied to the role, not to each person one by one. Easier to manage.
            \item Least privilege is simple: give each role only what that role needs.
        \end{itemize}

        \begin{notebox}[Note: research needs one extra rule]
            RBAC alone is not enough for the conflict-of-interest rule, because that rule depends on
            \textbf{history}: once a researcher touches Group A's data, they must be blocked from Group B's
            data afterward. This is exactly what the \textbf{Chinese Wall model (Brewer--Nash)} is built for.
            So we add a Chinese Wall on top of the Researcher role: once a researcher picks a side, the wall
            blocks the other side.
        \end{notebox}

        \begin{notebox}[Note: why not Bell-LaPadula or Biba alone]
            Bell-LaPadula and Biba use fixed security levels (like ``secret'' or ``high integrity''). They do
            not naturally handle ``only my own course'' or ``pick one side and stay there''. RBAC plus Chinese
            Wall fits this scenario better.
        \end{notebox}

        \begin{takeawaybox}
            Main model: RBAC, one role per type of user. Extra rule: Chinese Wall for researchers, so no one
            can see both sides of a conflict of interest.
        \end{takeawaybox}

    \section{Part IV: Access Control Matrix}

        An access control matrix lists every subject as a row and every object as a column. Each cell shows
        what that subject can do to that object.

        \begin{notebox}[Legend]
            \textbf{R} = read, \quad \textbf{W} = write/update, \quad \textbf{C} = create, \quad
            \textbf{O} = owns the record, \quad \textbf{--} = no access.
        \end{notebox}
